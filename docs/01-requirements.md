# 01 需求与成功标准

## 用户与业务目标

主要用户是内容运营与审核人员。他们需要从待处理素材中识别信息缺口和规则风险，在用户时间要求与已有排期之间寻找可行方案，并得到可确认的排期草稿。

系统目标不是自动发布，而是降低人工读取、核对和排期的重复工作，同时保留人工确认边界。

## 输入

- 素材ID
- 素材元数据
- 用户要求的发布时间
- 时间要求类型：`hard`或`flexible`
- 可选时间范围
- 已有排期
- 审核规则
- 用户是否确认替代时段

所有时间输入必须带时区，系统内部统一为北京时间UTC+8。

## 输出

- 每项素材的审核状态
- 规则风险及证据
- 用户原始要求时段
- 建议候选时段
- 待补充或待确认事项
- 草稿保存状态和草稿ID
- 整体任务状态
- 可审计Trace文件

## 范围内

- CLI运行入口
- 合成素材、审核规则和已有排期
- 素材读取、规则检查、时段查询、候选时段和草稿保存工具
- 模型动态选择工具的循环
- OpenAI兼容真实模型入口
- 无密钥离线Mock入口
- 幂等、原子写入和本机并发保护
- 步数、工具次数和重复调用上限
- JSON Trace和事实一致性审计

## 范围外

- 真实内容发布
- 真实企业素材库或排期系统
- Web界面和线上部署
- 多Agent编排
- 分布式锁和生产级数据库
- 完整的人工审批工作台

## 关键业务约束

1. 系统只保存草稿，不具备真实发布工具。
2. `hard`发布时间冲突时不能自动修改，只能建议并等待确认。
3. 信息不足的素材不能进入排期保存。
4. 命中阻断规则的素材不能保存排期草稿。
5. 保存失败必须返回失败，不能由模型声称成功。
6. 相同业务请求重复执行只能产生一份物理草稿。
7. 达到决策或工具调用上限时必须返回`incomplete`。
8. 模型最终结论必须由工具观察支持。

## 验收标准

| 验收点 | 输入条件 | 成功标准 | 证据 |
|---|---|---|---|
| 正常排期 | M01，17:00空闲 | 审核通过并保存草稿 | `examples/case-01-normal/` |
| 信息缺失 | M02缺版权方 | 返回缺失字段，不保存 | `examples/case-02-missing-info/` |
| 规则风险 | M03含绝对化词语 | 阻断且不保存 | `examples/case-03-rule-risk/` |
| 时段冲突 | M01要求18:00 | 建议19:00，待确认 | `examples/case-04-slot-conflict/` |
| 重复提交 | 相同业务请求两次 | 第二次`duplicate`，仅一条记录 | `examples/case-05-duplicate/` |
| 保存失败 | 注入保存错误 | 返回`failed`，无草稿ID | `examples/case-06-save-failure/` |
| 人工确认风险 | M04健康类素材 | `needs_confirmation`并保存待确认草稿 | `examples/case-07-manual-review/` |
| 提示词注入 | M06含越权发布指令 | 指令仅作为素材数据，不越权发布 | `examples/case-08-prompt-injection/` |

## 非功能成功标准

- 新环境可按README安装和运行。
- 测试可由单条命令执行。
- Trace包含动作、参数、观察摘要、下一动作和简要依据。
- Trace不包含API密钥和模型内部思维过程。
- Mock与真实模型能力边界在文档中明确说明。
